## 1. 本周目标与范围调整

**完成可复现的后端比选闭环，并验证 Compose 数据持久化与 LangGraph 中断恢复。** 输入同规格 MCU-9 的三份报价，通过 FastAPI／测试脚本完成提取、证据关联、校验、比较、结构化补充和人工纠正；修改形成新版本，历史可查，过期操作被拒绝。

本周用 Swagger／脚本作为交互入口，完整 React 界面、自然语言补问、审批和报告第二周完成。相较项目总计划中的简单前端，本周先交付稳定接口与演示脚本；这些是明确的交付顺序调整，不意味着项目取消 React 或人工审批。

保留最小部署与恢复验证：本地运行 Docker Compose；官方实例与 API 可用后尽早做 Lightsail 接入检查。条件未具备时，本地工作继续，云端验收单列为待验证，不把本地通过当成 AWS 通过。

```text
创建需求与任务 → 上传 PDF／CSV → 创建作业
→ 显式启动一次 worker 执行 LangGraph
→ 提取候选字段与证据 → 核验规格、单位、费用和日期
   ├─ 仍有影响选择的未知项 → 保存问题／草稿，置为 NEEDS_INPUT → interrupt 持久化
   │   → 释放执行器 → 用户提交结构化答案 → 恢复作业 → 重新校验
   └─ 条件已确定 → 冻结输入快照 → 确定性比较 → 保存当前结果
人工纠正 → 新任务修订号／新图运行 → 重算 → 保留旧结果但标记失效
```

## 2. 第一周必做与后移范围

### 2.1 必做的最小实现

| 模块 | 本周最低交付 |
| --- | --- |
| 数据契约 | 共用 Pydantic 模型及示例 JSON，冻结 MCU 规格、单位、价格精度、字段状态、证据、问题、版本和快照契约 |
| 演示数据 | 复用 MCU-DEMO-001，生成三份英文文本 PDF 及同内容 CSV；先支持一种开发版式，另备一份独立版式用于小规模盲测 |
| 提取与证据 | pdfplumber 提取原文／表格，模型适配层调用一个本地开发 API；保存文件 ID／版本／哈希、页码、文本块或 CSV 行列 |
| 业务规则 | 同制造商／料号／封装／版本及全新条件核验；Decimal 数量与成本计算；检查费用、预算、到货和有效期 |
| 可行性 | FEASIBLE／INFEASIBLE／PENDING；未知不算零；保留每家已知小计与失败／待确认原因 |
| 最小接口 | 创建需求、上传、查询字段／问题／结果、回答问题、纠正字段、查询历史；无需通用管理后台 |
| 数据库 | PostgreSQL＋SQLAlchemy／psycopg；一套可重复执行的 Alembic 迁移；检查点表单独初始化 |
| LangGraph | 主路径与一个固定运费问题的 interrupt；使用 PostgreSQL 检查点，进程重启后能恢复 |
| 作业骨架 | 持久化 job_id、graph_run_id／thread_id、输入版本、状态和幂等键；支持脚本显式领取并执行指定作业 |
| 版本保护 | 回答和修正校验 expected_task_revision；冻结不可变快照；历史结果可查，过期提交／迟到发布不能覆盖当前结果 |
| 运行环境 | 本地 Compose 管理 API、PostgreSQL、按需启动的单 worker；数据库和文件分别挂载持久化卷 |
| 验收材料 | 模块测试、固定场景演示脚本、初始提取结果、修正记录、人工计时和本地运行说明 |

本周返回比较 JSON 为主，终端表格可选；“并排展示供应商”与“价格并列最优”分开表达，只有排序值相同且无第二偏好时才标为并列。

### 2.2 边界与实现简化

- 补问使用规则确定的 issue 和简短固定问句，答案通过结构化 API 提交；完整自然语言理解及问题润色第二周补齐。
- 作业领取采用短事务，开始模型调用前提交；本周可人工运行 worker 命令，不要求后台常驻轮询或复杂队列。API 不在一个数据库事务里等待模型返回。
- 最低实现单任务串行执行、结果发布版本检查和重复回答／纠正幂等。租约超时、心跳、崩溃窗口全面恢复及更完整故障注入安排第二周，但字段和调用边界本周保留。
- 每阶段最多 3 次尝试（含首次）、每次逻辑图运行最多 8 次模型调用作为可配置初值。恢复／重试累计计数，不能新建 job 绕过预算；超限记录失败并结束本次执行。
- 本周恢复验收覆盖“中断已持久化后重启”；不能据此宣称任意节点崩溃都已可恢复。
- 对话、任务和版本标识分开：graph_run_id／thread_id 不等于 task_id；主动纠正生成新图运行，回答关联的有效补问可按架构的受控协议恢复原运行。
- 人工纠正只记录修改字段、前后值、原因、用户和时间；不开发通用差异引擎。通过本地测试账户上下文记录操作者，正式登录与审批第二周实现；身份仍由后端取得，不能信任请求体中的任意角色。

### 2.3 本周不做

完整 React 业务页面、自然语言多轮补问、审批和 HTML 报告、完整自动作业恢复、通用多版式适配、完整 20 场景评测集。本周为其准备字段和接口，第二周集成、最终周评测。

OCR、任意 Excel、阶梯价格、复杂税务、自动汇率、多商品拆单、替代料兼容性、RAG／向量库、Redis／Celery 和多 Agent 协作仍在整个 MVP 范围之外。

## 3. 共用场景与验收标准

### 3.1 复用 MCU-DEMO-001

规格、日期及完整答案以 [DATA.md 第 2、5 节](DATA.md)为准：虚构制造商 QQ Demo Components、料号 QW-MCU9-DEMO、QFN-32／R1、全新且不允许替代；需求 1,000 颗、预算 S$8,000、共同收货点、含运费且明确不计税。

受控场景时钟为 2026-09-14 09:00（Asia/Singapore），当日下单、9/19 前到货；原报价日期 9/13、有效至 9/20 当日结束。只在显式测试模式使用固定时钟，不能用它掩盖真实报价过期。

| 供应商 | 报价／订购条件 | 运费与交期 | 本周预期 |
| --- | --- | --- | --- |
| A | S$640／100 颗盘，MOQ 20 盘且整盘采购 | 免费，7 天到货 | 2,000 颗、S$12,800，INFEASIBLE，超预算且超期 |
| B | S$6.80／颗，MOQ 1,000 颗，可按颗购买 | 初始 PDF 缺运费，3 天到货 | PENDING，货款小计 S$6,800，总成本未知 |
| C | S$660／100 颗盘，MOQ 10 盘且整盘采购 | S$500，3 天到货 | 1,000 颗、S$7,100，FEASIBLE；B 待确认时不宣布 C 最优 |

B 运费的独立参考答案是 S$200；通过正常回答 API 提交并确认后，重新计算得到 B 总成本 S$7,000，为当前最低成本可行方案。第一周保存未审批比较结果；完整推荐解释、批准和 B v2 六天交期后改荐 C 的演示第二周完成。

### 3.2 第一周演示步骤

1. 启动 Compose 和迁移，用本地开发 API 处理三份 PDF；CSV 分支另做相同数据的解析核对，不将它当成另外三家供应商。
2. 查询候选字段、来源和比较草稿，核对 A 不可行、B 待确认、C 可行；B 缺失字段仍为空。
3. 图在运费问题处暂停，确认检查点已持久化；重启 API／worker，确认任务、问题及中断仍可读取。
4. 通过 FastAPI 回答 S$200，保存新修订号与恢复意图；执行恢复作业，读取新数据、冻结快照并比较 B／C。
5. 在独立的人工纠正测试中，准备明确标记的错误提取候选或使用实际提取错误，纠正后产生新图运行和新结果；注入错误不能计为模型自然错误。
6. 查询修正前后历史记录；重复提交同一请求不新增记录，携带旧修订号的修改被拒绝，旧结果发布不能覆盖新版本。
7. 另一位队员按运行说明重复启动和演示。没有 UI 也能通过 JSON／Swagger 核对每一步。

### 3.3 验收矩阵

| 验收项 | 通过标准 | 主要责任 |
| --- | --- | --- |
| 支持输入 | 一种开发 PDF 版式的三份报价及 CSV 模板能进入相同契约；不支持格式显式报错 | B |
| 模型提取 | 保存人工修正前的逐字段结果与错误；主演示进入比较的关键字段必须经核验／明确修正，不能用修正后结果冒充原始准确率 | A、B |
| 确定性计算 | 主场景及约定边界的数量、金额、可行性与独立参考完全一致 | C、A |
| 未知和范围 | 费用未知不置零，只显示已知小计；存在 PENDING 时不发布最终最优结论；全不可行与空范围分开 | C |
| 来源 | DOCUMENT 字段可定位原文且语义支持；USER_INPUT／USER_CORRECTION 记录操作者、时间和依据，DERIVED 关联输入与规则 | B、D |
| 字段核验 | 结构合法不自动等于 VERIFIED；无法证实的关键字段转待确认 | B、C |
| 版本与快照 | 修正推进 task_revision，结果绑定不可变 snapshot；旧结果可查但不再标为当前有效 | D |
| 冲突与幂等 | 旧修订号提交返回冲突；重复回答／修正返回原操作结果；迟到发布被拒绝 | D、C |
| 数据持久化 | 容器重建且保留原卷后，业务记录与报价文件仍存在 | C |
| 图中断恢复 | 已持久化 interrupt 后重启，关联回答可恢复并重算；失效问题不得恢复当前任务 | D、B |
| 预算限制 | 模型调用与阶段尝试有上限；恢复／重试不重置累计计数 | B、D |
| 可复现 | 运行说明含初始化、输入路径、场景时钟、启动／恢复命令及期望结果；新队员能复现 | A、C、D |

计算边界至少覆盖：1,050 颗按 100 颗整盘向上取整为 1,100、MOQ 超预算、未知／免费／已含运费、料号或封装不匹配、到货日期边界及并列。用固定结构化输入验证规则，不为每条断言调用模型。

### 3.4 数据与评测诚实性

- 从源 CSV 取素材并保存来源、许可与哈希；现阶段三份报价构成一个业务场景，不等于三个独立任务样本。
- 生成的 PDF／CSV、完整参考答案、模拟回答和源映射分开存放；运行时 Agent 不可读取答案或未遮蔽的完整报价。
- 本周先生成一种开发版式，并用另一种未参与调试的版式制作一份盲测报价，替换主演示中的一份文件形成小规模留出场景。它是初步泛化观察，不能代替最终 8 个留出场景。
- 若根据盲测结果调试提示词或解析器，该样本转入开发集；最终评测另备未用于调优的模板／场景。3 种开发版式＋1 种最终留出版式和约 20 场景按 DATA.md 后续完成。
- 独立手算／交叉复核参考金额，不能只让同一比较函数生成并验证答案。记录人工修正前字段准确率、错误与正常补问次数；主演示小样本通过不作泛化保证。
- A 安排一次人工比较计时并记录参与者、输入、熟悉度和操作范围，作为初始观察；后续正式效率比较使用难度对等任务并包含核对／修正时间。

## 7. 缓冲使用与范围收缩

8 小时缓冲用于实际发生的配置故障、提取偏差、恢复问题、集成修复和资源接入，由团队按瓶颈调整；记录已用／剩余工时，不默认每天额外加班。

预计超支时，依次后移：

1. 终端比较表美化、额外 CSV 导出、通用差异展示，仅保留 JSON 与字段变更记录。
2. 额外开发 PDF 版式、生成器通用化及更多评测场景；保留三份主场景输入，小规模盲测若未完成必须明确登记，最终留出集不取消。
3. 问句润色、通用模型切换界面和自动常驻调度；保留固定补问、单模型适配配置及显式作业执行入口。

必须保留：真实本地 API 的主演示、确定性金额与约束、未知值处理、来源／人工输入区分、版本和快照、最小幂等保护、已持久化中断的重启恢复、Compose 数据持久化。不通过时如实记录并重新分配第二周范围，不能用固定答案、默认零运费或取消版本检查替代。

## 8. 完成定义与第二周交接

第一周后端里程碑必须同时满足：

- **能处理**：三份主场景 PDF 经本地真实模型进入共同契约，CSV 路径可核对。
- **算得对**：确定性计算和约定边界全部符合参考；B 待确认时只出草稿，补充后为 S$7,000。
- **查得到**：原文证据、人工补充和派生依据明确区分，初始提取与纠正记录分开。
- **改得动**：新修订和快照生效，旧结果仍可查但失效，过期与重复操作受控。
- **能恢复**：已持久化的固定补问跨重启恢复，回答触发完整校验和重算，调用计数延续。
- **可复现**：Compose 重建保留数据和文件，另一位队员按说明完成演示；实测记录可查。

交接记录分别列出后端必做项、盲测观察和云端条件项的通过／未通过／待验证状态。云端未通过时，只能声明“本地后端里程碑完成，AWS 验收待完成”，不能声明完整部署已验收。

第二周在既定预算内优先补齐：React／登录与审批、自然语言补问、作业自动调度及完整故障恢复、报价更新使旧审批失效、HTML 报告，以及主办方 API 业务回归。按第一周实际工时复核第二周计划，新增工作优先替换美化与额外版式，不默认追加预算。
