# 偏好变更与决策说明回归指南

更新日期：2026-09-22。

## 最新验证结论

### 从成本优先切换到账期优先

Revision 11 本地只读核对显示原设置仍有 20 SGD 成本容差。该容差只适用于成本主指标，旧实现将合并设置冲突统一转换成“请说明希望调整的偏好”，使明确的账期请求看起来未被理解。

意图版本 `conversation-intent/1.1.0`：用户明确切换到非成本主指标时，对未明确保留的旧成本容差生成显式 `cost_tolerance_amount: null` 待确认变更。模拟回复明确提示将清除旧容差；正式状态仍须用户确认并应用。保留排除名单；仅变更次指标、仍以成本为主时不清除容差。未绕过主次指标或金额校验。

原句“账期最长优先，如果并列再选确认总成本最低的。”已用代码内合成偏好上下文真实调用验证通过（1 passed，1.78 秒），未向模型发送现有数据库任务或报价。模型正确输出最长账期主指标、最低成本次指标、清除成本容差。新增五种非成本主指标的继承清理回归及清理说明展示测试。

### 审核入口修复

“待处理事项”导航现在始终可见，不再依赖当前任务是否存在阻塞 issue。已完成任务进入审核页不再自动跳回决策结果；没有问题时展示空状态。可修正字段按当前比较范围与已排除供应商分组，已排除供应商的未解决阻塞审核项仍可人工核对，不会因其不影响当前推荐而丢失处理入口。核对字段本身不清空排除名单。

聊天中 `selection_review_required` 失败信息提供“前往集中审核”链接，定位到已排除供应商的审核区域。人工验证：点击链接，核对 Semitech 的字段并保存；重新分析完成后回到助手提出重新纳入请求。无须重传全部文件，也不直接跳过审核。

此次只修改前端入口和审核呈现，未改业务数据库或放宽后端审核门禁。回归覆盖无阻塞 issue 的导航、完成后的空状态、已排除字段的提交，以及聊天跳转链接。

- 后端与规则：401 passed、19 skipped、4 xfailed；前端：55 passed；生产构建通过（仍有大 bundle 警告）。跳过项包含需显式启用的真实模型与 PostgreSQL 测试，不表示自动覆盖所有环境。
- 另行启用真实模型：隔离任务模拟、事实问答、确认及应用验收通过；三组多轮意图（承接前文、容差 10 改 20、重新纳入 Semitech）通过。多轮测试命令为 `RUN_CONVERSATION_LIVE=1 .venv/bin/python -m dotenv -f .env run -- .venv/bin/python -m pytest tests/backend/test_conversation_routing.py -q`，实测 11 passed（含 8 项单元测试），11.90 秒。
- 新增前端回归证明阶段事件只影响对应待回复消息；应用 Scenario 后清空旧结果缓存，并导航到最新决策地址及新版本状态。
- 现有 demo3 任务通过强制只读 PostgreSQL 连接做了**本地计算**，没有调用外部模型、没有保存变更：Revision 8 保留 SUP-030 排除时，10 SGD 容差模拟推荐 SUP-024；尝试重新纳入 SUP-030 时，由于它仍有待审核字段，正确触发集中审核门禁。因此不能直接把 SUP-030 当作此任务当前的预期赢家。
- 将现有任务上下文发送到模型的复测被安全审查拒绝。已确认其五份报价标记为合成数据，仍等待用户明确授权该任务外发；没有绕过拦截。当前真实模型通过结论只适用于隔离数据，不冒充现有任务端到端验证。

## 独立意图路由实施记录（尚未完成全流程验收）

聊天 Worker 现先调用 `route_conversation_intent`，再分为模拟、事实解释、澄清和不支持四条路径。模拟必须包含非空结构化变更，不允许缺失变更后静默回到旧结果解释。意图输入不包含旧推荐叙述；主次偏好合并后复用 `DecisionPreferences` 校验。模拟使用既有确定性说明，不额外请求模型撰写数字与引用。事实问答使用剩余调用预算，整轮上限三次模型请求。

2026-09-22 使用当前 `.env` 模型做了真实调用，仅提供合成意图上下文，不写入已有业务任务，也未向模型传入参考答案：

- 已经按历史准时率排序时，排除 Semitech 请求生成 SUP-030 排除列表，没有混同 Components。
- 重新纳入 Semitech 生成清空排除列表；恰好当天请求进入日期语义澄清；批准采购请求返回不支持。
- **首次真实调用发现失败**：“快一点，但别太贵”被转换成最快优先、成本次优先，未询问上限。补充价格约束完整性契约后，原句及“最快到货，但价格也得能接受”两次复测均返回 `COST_LIMIT`；原始 10 新币请求复测仍通过。这不等于证明所有同义表达均已覆盖。

新增 `tests/backend/test_conversation_routing.py` 覆盖模拟路由、空变更禁止降级、非法供应商、合并后主次冲突及共享调用预算。阶段回归为 **399 passed、15 skipped、4 xfailed**（在随后价格约束补测和供应商名称目录补充之前运行）。待补齐：分阶段诊断及前端展示、既有上下文只读真实复测、隔离任务完整确认与应用、完整最终回归。不得据此要求用户重传全部数据或宣称全部修复完成。

- 初次真实模型隔离验收通过模拟、确认、应用、新版本差距读取，并验证零新增解析及修正批次保留（1 passed，2.90 秒）。随后扩展普通事实问答，实际出现 `monetary claim is attributed to the wrong supplier`，整项验收失败（44.50 秒）。该失败尚待针对实际回答定位，不能用初次通过代替扩展后的验收。测试已增加仅针对合成测试内容的失败回复捕获。

- Scenario 应用与手动重新分析共用结构化输入复用逻辑。优先保留最近已审核工作流中的人工修正；其次复用匹配文件、模型配置和字典的已提交报价。复用后仍执行当前需求下的审核和确定性重算，不复用旧审批结论。
- 主计算和差距接口共用参与比较范围的构建方法。已排除供应商的待审核字段不阻塞当前范围；重新纳入时仍须审核。
- 差距请求可绑定具体 `expected_result_id`。同版本重跑后，旧结果的详情请求会被拒绝，避免混用两次结果。页面明确展示加载错误并提供重试，不再统一声称“未保存差距数据”。
- 模型识别结构化偏好变更，公共计算模块执行模拟，服务端根据真实排序轮次组织中文说明：结论、适用规则、容差上限、候选报价、选择依据、确认生成 Scenario。
- 说明保存为 `DECISION_PREVIEW`，引用标记为 `SIMULATION:`；与当前正式结果分开。并列、缺失历史数据、空范围均不伪造唯一赢家。确认生成与正式应用仍是两个操作。
- 报价解析失败提示包含阶段、文件标识、错误码及已用模型调用数；不暴露供应商模型端点或凭据。
